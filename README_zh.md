MicroSocks - 多线程、小型、高效的 SOCKS5 服务器。
===========================================================

一个 SOCKS5 服务，您可以在远程服务器上运行它，以通过它们隧道连接，
如果 SSH 因某种原因无法满足您的需求。

它非常轻量级，资源占用也很少：

对于每个客户端，都会生成一个具有低堆栈大小的线程。
主进程基本上不消耗任何资源。

唯一的限制是文件描述符的数量和 RAM。

它还设计得非常健壮：它通过简单地拒绝新连接来优雅地处理资源耗尽，
而不是像现在大多数其他程序那样调用 abort()。

另一个优点是易于使用：无需配置文件，所有操作都可以
从命令行完成，甚至不需要任何参数即可进行快速设置。

历史
-------

这是“rocksocks5”的继任者，它的编写考虑了不同的目标：

- 优先使用标准 libc 函数，而不是自制的函数
- 没有人为限制
- 不以最小的二进制文件大小为目标，而是以最小的源代码大小、
  最大的可读性、可重用性和可扩展性为目标。

因此，ipv4、dns 和 ipv6 开箱即用，并且可以使用相同的代码，
而 rocksocks5 有几个编译时定义，可将生成的二进制文件的大小降至极值，
例如启用 ipv4 支持时静态链接的 10 KB。

尽管如此，如果针对大小进行优化，这个程序在针对 musl libc 进行静态链接时甚至不到 50 KB。
即使在最便宜的路由器上也可以轻松使用。

命令行选项
--------------------

    microsocks -1 -q -i 监听ip -p 端口 -u 用户 -P 密码 -b 绑定地址 -w 白名单

所有参数都是可选的。
默认情况下，监听ip 为 0.0.0.0，端口为 1080。

- `-i listenip`: 指定服务器监听的 IP 地址。默认为 `0.0.0.0`，表示监听所有网络接口。
- `-p port`: 指定服务器监听的端口。默认为 `1080`。
- `-u user`: 设置身份验证的用户名。如果设置了此选项，则必须同时设置 `-P` 选项。
- `-P passw`: 设置身份验证的密码。如果设置了此选项，则必须同时设置 `-u` 选项。
- `-b bindaddr`: 指定传出连接绑定的源 IP 地址。
- `-w wl`: 以逗号分隔的 IP 地址白名单，允许这些地址无需身份验证即可访问代理。例如：`-w 127.0.0.1,192.168.1.1`。
- `-1`: 激活“一次性验证”模式。一旦某个 IP 地址成功通过用户名/密码验证，它将被添加到白名单中，之后该 IP 地址的连接将不再需要身份验证。此选项需要与 `-u` 和 `-P` 一起使用。
- `-q`: 禁用日志记录。
  例如，使用 curl 进行一次身份验证：

    curl --socks5 用户:密码@监听ip:端口 任何网址


核心功能
--------------------

### SOCKS5 身份验证

MicroSocks 支持以下 SOCKS5 身份验证方法：

- **无身份验证**：当未使用 `-u` 和 `-P` 选项时，代理服务器允许任何客户端连接而无需身份验证。
- **用户名/密码**：通过 `-u` 和 `-P` 选项设置用户名和密码后，客户端必须提供正确的凭据才能使用代理服务。
- **一次性验证**：通过 `-1` 选项激活。在客户端首次使用用户名和密码成功验证后，其 IP 地址将被加入白名单，后续连接无需再次验证。这对于不支持 SOCKS5 身份验证的应用程序非常有用。

### 连接处理

MicroSocks 为每个客户端连接创建一个独立的线程。这种多线程架构允许服务器高效处理并发连接。服务器主线程负责接受新的客户端连接，然后为每个连接创建一个新线程进行处理，主线程本身不消耗大量资源。

每个线程的堆栈大小都经过优化，以最大限度地减少内存使用。如果服务器资源耗尽（例如，文件描述符或内存不足），它将拒绝新的连接，而不是崩溃，从而确保服务器的稳定性。

支持的 SOCKS5 功能
-------------------------
- 身份验证：无、密码、一次性
- IPv4、IPv6、DNS
- TCP（目前不支持 UDP）

故障排除
---------------

### 段错误

如果您遇到段错误（segmentation fault），这通常与线程的堆栈大小有关。您可以尝试通过以下步骤解决：

1. 打开 `sockssrv.c` 文件。
2. 找到 `THREAD_STACK_SIZE` 的定义。
3. 以 4KB 的步长增加该值（例如，从 `32*1024` 增加到 `36*1024`）。
4. 重新编译并运行服务器。

如果增加堆栈大小解决了问题，请考虑提交一个拉取请求，以便项目可以根据您的平台进行调整。

### 连接被拒绝

如果您发现连接被拒绝，尤其是在高负载情况下，这可能是由于系统资源耗尽（如文件描述符或内存不足）。MicroSocks 在这种情况下会拒绝新的连接以保持稳定。您可以检查系统日志或使用 `ulimit -n` 命令查看文件描述符的限制。

### 身份验证失败

- **用户名/密码**：确保您在客户端和服务器上使用的用户名和密码完全匹配。
- **一次性验证**：如果您使用的是一次性验证（`-1` 标志），请确保您已经使用支持 SOCKS5 身份验证的客户端（如 `curl`）成功进行了一次身份验证。

microsocks 使用最小的安全线程堆栈大小来最小化总体内存使用。
